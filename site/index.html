The 7B ceiling

Every token reads every weight. Once.

Decoding one token streams the whole model through the GPU, so memory bandwidth sets the limit, not compute. This M2 Pro reads 197 GB/s, which caps a 4.08 GB model at about 48 tok/s.

MLX Runner decodes Mistral 7B at 41.0 tok/s, about 85% of that cap. Faster means more bandwidth (an M-series Max: about 400 GB/s), fewer bits, or speculative decoding (mlxr run --spec).

An engine written from scratch, for Metal.

No mlx-swift: MLX Runner runs MLX models on its own kernels, from the same files mlx-lm reads. Any compatible mlx-community repo works without conversion.

  • Prefill on tensor tiles

    Quantized GEMMs on simdgroup_matrix tiles and flash attention. Short follow-ups get an 8- or 16-token tile.

  • KV-cache prefix reuse

    Prompt tokens shared with the previous request are skipped, so follow-ups start almost instantly.

  • Nothing else

    Swift plus Apple frameworks. No SwiftPM packages, no vendored code, no Python.

Command line

mlxr, the same engine in your terminal.

Search, download, run, serve and benchmark from a shell, on the app's model library. Every number on this page came from mlxr bench.

  • mlxr download mlx-community/Qwen3-4B-4bit
  • mlxr run <model> -p "Explain RoPE" --no-think
  • mlxr serve <model> --port 1234
  • mlxr bench <model>

Your tools already speak its API.

OpenAI-compatible: the Responses API with typed streaming events, Chat Completions and function tools. Point any OpenAI SDK at it. These exchanges are real, captured from Qwen3 0.6B.

# Chat Completions with a function tool
curl http://localhost:1234/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen3-0.6B-4bit",
       "messages": [{"role": "user",
                     "content": "What is the weather in Berlin right now?"}],
       "tools": [{"type": "function", "function": {"name": "get_weather",
                   "parameters": {"type": "object",
                                  "properties": {"city": {"type": "string"}},
                                  "required": ["city"]}}}]}'

# The model calls it. Reply with a "tool" message and it finishes the turn.
"finish_reason": "tool_calls",
"message": {"role": "assistant", "content": null,
            "tool_calls": [{"id": "call_d450Vb67…", "type": "function",
                            "function": {"name": "get_weather",
                                         "arguments": "{\"city\":\"Berlin\"}"}}]}
from openai import OpenAI
client = OpenAI(base_url="http://localhost:1234/v1",
                api_key="not-needed-on-localhost")

tools = [{"type": "function", "function": {"name": "get_weather",
          "parameters": {"type": "object",
                         "properties": {"city": {"type": "string"}},
                         "required": ["city"]}}}]
r = client.chat.completions.create(
    model="Qwen3-0.6B-4bit", tools=tools,
    messages=[{"role": "user",
               "content": "What is the weather in Berlin right now?"}])
call = r.choices[0].message.tool_calls[0]
print(call.function.name, call.function.arguments)  # get_weather {"city":"Berlin"}
# Responses API, streamed, same tool
curl http://localhost:1234/v1/responses \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen3-0.6B-4bit", "stream": true,
       "input": "What is the weather in Berlin right now?",
       "tools": [{"type": "function", "name": "get_weather",
                  "parameters": {"type": "object",
                                 "properties": {"city": {"type": "string"}},
                                 "required": ["city"]}}]}'

# Typed events deliver a reasoning item (Qwen3), then the call
{"type": "function_call", "call_id": "call_lptFNQuX…",
 "name": "get_weather", "arguments": "{\"city\":\"Berlin\"}",
 "status": "completed"}
  • Tool calling. tool_choice auto, none, required or a named function, parallel calls, and the full call → result → answer loop. Prompts use each model's native format, byte-identical to the official templates.
  • Safe by default. Localhost only; other Host headers and unknown browser Origins refused; JSON bodies, timeouts and size limits. An API key is required on the LAN.
  • Reasoning included. Qwen3 thinking comes back as reasoning_content or a reasoning item.

Model files are untrusted input.

It runs files from the internet on your GPU and can open a port. It is built like it knows that.

  • Validated before the GPU

    safetensors headers, tensor offsets, config dimensions, token ids and every weight shape are checked first.

  • Verified downloads

    Every LFS file is checked against its SHA-256 from the Hub. Your Hugging Face token lives in the Keychain.

  • Signed updates

    An update installs only if its Ed25519-signed SHA256SUMS, its checksum and the code signature all verify, then swaps in atomically.

  • Collects nothing

    Prompts and replies never leave your Mac. The only network calls are Hugging Face for models and GitHub for updates.

First launch

Drag MLX Runner to Applications. It is ad-hoc signed, not notarized by Apple, so macOS blocks the first launch: right-click it and choose Open, or run:

xattr -dr com.apple.quarantine "/Applications/MLX Runner.app"

Updates then arrive through Check for Updates…, verified before they install. For the CLI, copy mlxr from the archive to a directory on your PATH.

Verify before you run it

Every release is built by GitHub Actions from a tagged commit. Three independent checks prove the file you have is that build.

  1. Download the app, the checksum list and its signature

    curl -LO https://github.com/BackendStack21/mlx-runner/releases/download/<tag>/MLX-Runner-<version>-macos-arm64.dmg
curl -LO https://github.com/BackendStack21/mlx-runner/releases/latest/download/SHA256SUMS
curl -LO https://github.com/BackendStack21/mlx-runner/releases/latest/download/SHA256SUMS.sig

    For the CLI, download mlxr-<version>-macos-arm64.tar.gz instead.

  2. Check the SHA-256

    shasum -a 256 -c SHA256SUMS --ignore-missing

    Expect MLX-Runner-<version>-macos-arm64.dmg: OK.

  3. Check the release signature

    curl -fsSLo mlx-runner.pub https://raw.githubusercontent.com/BackendStack21/mlx-runner/main/packaging/update-key.pub
openssl pkeyutl -verify -pubin -inkey mlx-runner.pub -rawin -in SHA256SUMS -sigfile SHA256SUMS.sig

    Expect Signature Verified Successfully (needs OpenSSL 3: brew install openssl).

  4. Check where it was built

    # GitHub CLI: https://cli.github.com
gh attestation verify MLX-Runner-<version>-macos-arm64.dmg --repo BackendStack21/mlx-runner

    Sigstore provenance in a public transparency log, tied to this repository's release workflow and commit.
