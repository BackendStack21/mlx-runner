New in 2.2 · opt-in

Sieve: up to 15% faster decode, by approximating the output layer.

A model's last layer scores every token in the vocabulary on every step, though the sampler uses only a handful of those scores. With Sieve on, a small 4-bit approximation scores them all, and the exact score is computed only for the likeliest (up to 16,384). Output can differ, so it is off by default. Each model is fitted once, in one to six minutes.

  • It changes output

    The approximation is not exact, so some answers diverge; the table counts them. Off, it costs nothing and output is unchanged. A model that has not been fitted runs at its normal speed.

  • Where it pays

    The gain follows the output layer's share of a step: 8–15% on models up to 4B with a large vocabulary, 4% on Qwen3 8B, and not worth turning on for Phi-3.5 mini or Mistral 7B.

  • Not measured

    Benchmark scores, perplexity, long contexts, tool calls, thinking, and sampler settings other than greedy and the default. The fit and its test use the model's own short answers. Models over 8B could not be fitted on 16 GB.

mlxr sieve mlx-community/Qwen3-0.6B-4bit   # fit once
mlxr run mlx-community/Qwen3-0.6B-4bit "Explain RoPE" --sieve balanced

In the app: the Sieve switch and Fit button in the chat inspector. Also --sieve balanced on mlxr serve.

Method, full tables and limits

Engine

Written from scratch, for Metal.

No mlx-swift: MLX Runner runs MLX models on its own kernels, from the same files mlx-lm reads. Any compatible mlx-community repo works without conversion.

  • Prefill on tensor tiles

    Quantized GEMMs on simdgroup_matrix tiles, each weight tile dequantized once and shared by 32 tokens, and flash attention.

  • KV-cache prefix reuse

    Prompt tokens shared with the previous request are skipped, so follow-ups start almost instantly.

  • Sparse attention, on by default

    From 5,128 tokens of context each new token attends to the first and latest tokens plus the 2,048 that score highest. Decode at 30K is 1.4–3× faster than dense, and output changes: perplexity rises by about 3% or less on most models measured, 8% on Gemma 4 E2B. Speed and quality per model.

Local server

Your tools already speak its API.

OpenAI-compatible: the Responses API with typed streaming events, Chat Completions and function tools. Point any OpenAI SDK at http://localhost:1234/v1. This exchange is real, captured from Qwen3 0.6B.

curl http://localhost:1234/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen3-0.6B-4bit",
    "messages": [{"role": "user",
      "content": "What is the weather in Berlin right now?"}],
    "tools": [{"type": "function", "function": {
      "name": "get_weather",
      "parameters": {"type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]}}}]}'

# The model calls it. Reply with a "tool" message and it finishes the turn.
"finish_reason": "tool_calls",
"message": {"role": "assistant", "content": null,
  "tool_calls": [{"id": "call_d450Vb67…", "type": "function",
    "function": {"name": "get_weather",
      "arguments": "{\"city\":\"Berlin\"}"}}]}
  • Tool calling on Qwen, Llama 3.1+ and Mistral v0.3 models (Gemma and Phi-3.5 have no tool format): tool_choice, parallel calls and the full call → result → answer loop.

Endpoints, and what is rejected

Security

Model files are untrusted input.

MLX Runner runs files from the internet on your GPU and can open a port, so everything it reads is checked first. Security policy.

  • Validated before the GPU

    safetensors headers, tensor offsets, config dimensions, token ids and every weight shape are checked first.

  • Verified downloads

    Every LFS file is checked against its SHA-256 from the Hub. Your Hugging Face token lives in the Keychain.

  • Signed updates

    An update installs only if its Ed25519-signed SHA256SUMS, its checksum and the code signature all verify.

  • Collects nothing

    Prompts and replies never leave your Mac. The only network calls are Hugging Face for models and GitHub for updates.

First launch

Drag MLX Runner to Applications. It is ad-hoc signed, not notarized by Apple, so macOS blocks the first launch: right-click it and choose Open, or run:

xattr -dr com.apple.quarantine "/Applications/MLX Runner.app"

Updates then arrive through Check for Updates…, verified before they install.

Only the CLI

mlxr is a single binary and doesn't need the app. In Terminal:

curl -LO https://github.com/BackendStack21/mlx-runner/releases/download/<tag>/mlxr-<version>-macos-arm64.tar.gz
tar -xzf mlxr-<version>-macos-arm64.tar.gz
sudo mkdir -p /usr/local/bin
sudo install -m 755 mlxr-<version>-macos-arm64/mlxr /usr/local/bin/mlxr
mlxr   # prints help

Use curl as shown: macOS quarantines an archive downloaded in a browser, and the binary then won't start. To update, run mlxr upgrade (sudo mlxr upgrade when it is in /usr/local/bin); 1.x has no upgrade command, so run these commands once. To check the archive first, see Verify.

Verify

Verify before you run it.

Every release is built by GitHub Actions from a tagged commit. Its checksum, the release signature and the build provenance tie the file you have to that build.

Show the commands

  1. Download the app, the checksum list and its signature

    curl -LO https://github.com/BackendStack21/mlx-runner/releases/download/<tag>/MLX-Runner-<version>-macos-arm64.dmg
curl -LO https://github.com/BackendStack21/mlx-runner/releases/latest/download/SHA256SUMS
curl -LO https://github.com/BackendStack21/mlx-runner/releases/latest/download/SHA256SUMS.sig

    For the CLI, download mlxr-<version>-macos-arm64.tar.gz instead.

  2. Check the SHA-256

    shasum -a 256 -c SHA256SUMS --ignore-missing

    Expect MLX-Runner-<version>-macos-arm64.dmg: OK.

  3. Check the release signature

    curl -fsSLo mlx-runner.pub https://raw.githubusercontent.com/BackendStack21/mlx-runner/main/packaging/update-key.pub
openssl pkeyutl -verify -pubin -inkey mlx-runner.pub -rawin -in SHA256SUMS -sigfile SHA256SUMS.sig

    Expect Signature Verified Successfully (needs OpenSSL 3: brew install openssl).

  4. Check where it was built

    # GitHub CLI: https://cli.github.com
gh attestation verify MLX-Runner-<version>-macos-arm64.dmg --repo BackendStack21/mlx-runner

    Sigstore provenance in a public transparency log, tied to this repository's release workflow and commit.
